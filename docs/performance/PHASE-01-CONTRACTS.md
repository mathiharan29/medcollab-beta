# Phase 01 shared harness contracts

Implementation follows [Phase 01](plan/PHASE-01-HARNESS-CONTRACTS.md) and the [shared architecture](plan/ARCHITECTURE-AND-CONVENTIONS.md). Source remains `4c01dc24247aa95a73e286a2b42c7f2f81257c7a`; starting harness revision was `7b065078d93045ff8a1a01801ce2258236411a85`. All 45 original cases and their owner phases remain unchanged and NOT_IMPLEMENTED / NOT_EXECUTED. There are no concrete scenarios, workload entry points, backend changes or workflows.

The public entry point is [lib/index.mjs](../../tests/performance/lib/index.mjs). Importing it defines interfaces and reads bundled JSON metadata; it does not create a journal, invoke hooks, load Artillery/Socket.IO code, resolve DNS, start services or contact a target. | Required interface | Implementation and contract |
|---|---|
| `validateRunConfig(raw)` | Strict schema and semantic checks, immutable result, known case/variant/dependency closure, all finite budgets and deadlines, E1 caps, limiter provenance and provider budgets. No coercion, unknown fields, environment-derived credentials or target contact. |
| `assertIsolatedTarget(config, identityEvidence)` | Reviewed allowlist plus Ed25519-signed orchestrator evidence. Checks run/config/source/harness/environment/topology/owner/namespace, exact URL/address sets, finite lease, budget ceilings and blocked egress/isolated credentials. Returns an immutable process-local authorization handle. |
| `captureProvenance(inputs)` | Takes validated `config`, source `lockfileHashes` and an orchestrator/service `executionIdentity`. Captures actual local Node/OS/architecture/timezone/time, hashes the actual harness lockfile and records installed manifest versions without importing dependencies. Missing installations are `null`. Source lock hashes must come from the pinned, read-only source/orchestrator evidence; backend lock evidence is mandatory. |
| `allocateActors(seed, profile, workerPartition)` | Versioned deterministic user/device manifest; global user-index partitioning yields disjoint workers and keeps user/device identities separate. Profile: `{schemaVersion:1,runId,users,devicesPerUser,maxActors}`; partition: `{index,count}`. No accounts or database records created. |
| `registerOwnedResource(journal, resource)` | Persists/fsyncs exact ownership and create intent before caller mutation; returns `{journalId,resourceKey,runId}`. Null IDs explicitly represent an unknown server-generated ID. |
| `recordStage(actionId, stage, monotonicTime, context)` | Run-scoped ordered stages, explicit clock domain/attempt, bounded correlation metadata, receipt copies and persisted IDs. Event arrival before HTTP response is permitted. No patient/message/provider payloads are retained. |
| `recordOutcome(actionId, outcome)` | Exactly one terminal action outcome: success/failure/ambiguous/censored/unfinished. Success requires independent reconciliation and any declared audience accounting; HTTP acceptance alone is insufficient. |
| `finalizeRun(run, oracleResults, cleanup)` | Strict versioned report, separate case implementation/review/execution/threshold fields, actual accounting, oracle/artifact references, primary/cleanup failures and exit status. Unknown/missing observations cannot produce PASSED. |
| `cleanupOwnedResources(journal, authorization)` | Only exact journal resources in a signed owner/environment/namespace; bounded retries/deadlines, independent ownership/absence evidence, durable cleanup intents and verified deletion. | `defineScenario(definition)` | Exact metadata and prepare/run/observe/reconcile/cleanup hooks. Definition invokes nothing. Every exposed hook goes through authorization/config/run identity, capability and deadline checks. Missing capability is BLOCKED_PREREQUISITE. |

`recordStage` and `recordOutcome` are most conveniently used as bound methods on `ctx.ledger`, created by `createActionLedger`. Their signatures match the shared plan. Stateless named exports also exist: `context.ledger` / `outcome.ledger` selects the run handle and is removed before serialization. No global run singleton or competing delivery library is introduced. Phase 03 still owns `recordDelivery`, cohorts and Socket.IO readiness implementations.

Additional foundation helpers are `createClock`, `createBudgetGuard`, `getRequiredMetrics`, `createSeededRandom`, `defineSyntheticResource`, `createResourceJournal`, `recordResourceOutcome`, `withOwnedResources`, `createMetrics`, `mergeHistograms`, `invokeScenarioHook`, `assertPinnedDestination`, `writeRunReport`, and `exitCodes`.

## Configuration and execution authorization

[Run schema](../../tests/performance/schemas/run-config.schema.json) and [template](../../tests/performance/config/run-template.json) cover repository/source/harness/run identity, case variants, E1-E5 identity/topology, service URL/address set, workload seed/distribution, data/index manifests, provider modes, limiter settings, instrumentation, finite budgets/deadlines, baseline and threshold references, and bounded journal/ledger retention.

The template is a structural example, not an approved workload: `executionAuthorized=false`, all rates/work totals/provider budgets are zero, hashes/identity are placeholders, and its future variant is unregistered. [Target policy](../../tests/performance/config/target-policy.json) has no targets or trusted keys. Merely changing a URL or setting a boolean cannot authorize a target. No policy-injection/bypass argument or environment variable exists.

Future authorized execution requires a reviewed policy change containing the exact isolated origin, address set, service/environment/topology, owner/namespaces, budget ceilings and public verification key. Never add private keys or credentials. The signed payload is described by [identity schema](../../tests/performance/schemas/identity-evidence.schema.json); the signature is base64 Ed25519 over canonical UTF-8 JSON of `payload`, with lexicographically sorted object keys. Evidence includes a config digest and a finite issuedAt/expiresAt lease. The policy's `diskReserveBytes` is a minimum reserve; other numeric budget ceilings are maxima. Known production hosts are additionally denied, but this denylist never substitutes for positive isolation evidence.

No DNS lookup or network enforcement is claimed by the identity checker. The trusted orchestrator must provide actual resolved-address evidence. Later HTTP/Socket.IO adapters must pin the approved peer addresses and call `assertPinnedDestination` for the actual TCP peer and HTTP/WebSocket origin, retaining TLS hostname verification. Redirects are disabled. A networked simulator must also be inside separately controlled test infrastructure. E5 real-provider access still needs a separately approved provider grant/adapter; this phase supplies none and signed identity requires default blocked egress.

Catalog variants are currently empty, so execution configuration cannot validate successfully yet. Later case owners register `{id,requiredMetrics:[...]}` in their existing case record, implement its scenario and preserve ownership/status distinctions. `getRequiredMetrics` combines those operation-specific requirements with common generator/SUT/DB metrics. Reports cannot remove those requirements through caller overrides. This defines the previously empty variant metadata shape without changing any existing ID or specification.

`createBudgetGuard(config)` is independent of a scheduler. Before traffic, future adapters must use `admit(kind,amount,monotonicTime)` for new connections, requests, messages, events, outbound deliveries, bytes and database growth; `admitProvider` accounts both total and individual provider calls. Sliding one-second windows are bounded, and count/byte/elapsed ceilings fail closed. `reserve/release` tracks connection/upload concurrency; `observeResources` checks measured memory, CPU, free disk and cost. Unknown resource measurements are rejected. These checks are not a substitute for the later independent watchdog/environment lease. E1 enforces at most 10 HTTP starts/s, 20 connections/accounts, 1 MiB upload fixtures, closed provider egress and B/C profiles; C additionally caps ten actors and ten minutes.

## Journal and failure lifecycle

`createResourceJournal({directory,config,authorization,cleanupAdapters,resume})` requires an existing absolute artifact directory and a live authorization handle. It creates one restrictive run/config-named JSONL journal and exclusive writer lock, using no broad directory creation or deletion. Every record has sequence, previous hash and content digest. Fsync completes before create intent returns. Before any creation intent, entry/byte headroom is reserved for acknowledgement and every bounded cleanup attempt/outcome, using a conservative schema-bounded maximum record size. New resources cannot consume that reserved capacity. Entry/byte limits block further mutation; truncated or inconsistent recovery fails closed and preserves evidence.

A resource has `type,id,intentId,namespace,ownerIdentity,runId,environmentId,leaseId,path` ([schema](../../tests/performance/schemas/resource.schema.json)). A server-generated ID can start as null; `recordResourceOutcome` durably binds its acknowledged exact ID. A lost response remains AMBIGUOUS/INTENT, never proof of absence. NOT_CREATED is allowed only with explicit never-dispatched evidence. Unknown IDs block cleanup; no prefix search/drop fallback exists. Ownership is recorded independently of application fields that Mongoose may strip.

Cleanup adapters implement `verifyOwnership(resource,authorization,signal)`, `remove(resource,authorization,signal)` and `verifyAbsent(resource,authorization,signal)`. Before deletion, independent evidence must exactly match ID, namespace, owner, run, environment, original creation lease and any exact file path. Already absent exact resources can be reconciled without another delete. Callbacks must enforce destination pinning, honor cancellation and perform idempotent exact deletion. Adapters are future phase work, not fake database implementations here.

Cleanup intent is durable before each attempt; outcome/retry state persists. A new, separately signed cleanup lease for the same run/config can resume the journal and reclaim only its exact expired old lock; an active lock cannot be replaced. Windows/process/filesystem crash semantics and concurrent-writer recovery still need authorized characterization. Corrupt/partial journals stay quarantined rather than guessing safe deletions.

`withOwnedResources` uses finally-style cleanup and preserves primary and cleanup failures separately. Its callback must use guarded hooks and complete bounded drain/reconciliation before returning. A timeout/cancellation can leave cooperative callbacks or remote work running; it therefore quarantines those failures as WORKER_QUIESCENCE_REQUIRED instead of deleting concurrently. Other cleanup timeouts do not retry potentially active work. Hard termination, external watchdogs and fault restoration belong to Phase 14/orchestration. No in-process Promise timeout is described as a hard process kill.

## Accounting, metrics and reports

`createActionLedger({runId,caseIds,operationIds,clockDomainId,limits})` exposes `beginAction`, `expectAudience`, stage/outcome recording and immutable `snapshot`. `limits` contains maxActions/maxStages/maxBytes. `createClock(clockDomainId)` supplies the actual local monotonic clock, wall clock and time origin; hooks require the ledger and clock domains to agree. Cross-worker timings still need external synchronization/uncertainty evidence. Each action retains a unique logical ID, case/variant/operation, attempts, ordered clock-domain stages, independent expected audience, persisted IDs and observed copies. Duplicate copies remain visible; identical-content actions are never merged. Missing/censored/ambiguous/unfinished work remains in terminal accounting, including observations after a failed response. Independent business oracles remain owned by later cases.

`createSeededRandom(seed,stream,maxDraws)` uses a versioned SHA-256 counter stream with a finite draw limit. It is for deterministic workload choices, not security credentials. `defineSyntheticResource` creates definitions only; actual dataset graphs/seeding belong to later owners, including Phase 10.

`createMetrics({definitions,maxSeries,maxObservations})` requires finite histogram boundaries and explicit low-cardinality label value sets. IDs are confined to bounded ledgers. Units are milliseconds, bytes, counts, rates/second or percent. `observe` keeps completed/censored/failed counts; censored durations are observation bounds, not completed latency. Missing observations have `availability=UNAVAILABLE,value=null,reasonCode`; they are never synthesized as zero. `mergeHistograms` merges matching buckets/counts and refuses incompatible layouts; it never averages percentiles.

`finalizeRun` takes a structurally valid configuration; started runs also require the immutable validated handle, historical signed-authorization evidence, provenance, timeline, budget accounting and installed dependency versions. `run` supplies `startedAt/endedAt` (both null if unstarted), provenance or null, ledger/metrics snapshots, artifacts `{artifactId,sha256}`, primaryFailures (redacted error classes), prerequisitesComplete, infrastructureValid, generatorValid, optional abortReason and optional thresholdEvaluation. Oracles are `{caseId,variant,status:PASSED|FAILED|UNAVAILABLE,evidenceRefs:[artifactId]}`; cleanup is `{status:COMPLETE|FAILED|BLOCKED|NOT_EXECUTED,remaining,failures}`. Missing setup metadata that cannot satisfy even the structural schema is a HarnessError for the later orchestrator to report as setup failure, not a manufactured run envelope.

The [report schema](../../tests/performance/reporting/schema.json) embeds configuration, provenance, budgets/achieved counts, required/unavailable metrics, correctness stages, oracle evidence, cleanup, artifacts and all selected variant outcomes. Catalog implementation/review status is not rewritten. Missing variant observations, oracle evidence, required metrics, terminal accounting or calibration cannot pass. Unknown baseline/product policy remains INCONCLUSIVE with BASELINE_REQUIRED/PRODUCT_DECISION_REQUIRED. A thresholdEvaluation is future externally produced analysis evidence, not a statistical evaluator or invented threshold in Phase 01. The evaluation must carry policyRef/policyHash, baselineArtifactId/baselineSha256 and evidenceRefs; the exact configured baseline and policy hashes must also be present in artifacts. Evidence references must resolve to immutable artifacts and an approved baseline/policy; Phase 17 owns the actual comparisons.

Exit codes: PASSED=0, FAILED_FUNCTIONAL=1, FAILED_PERFORMANCE=2, INVALID_GENERATOR=3, FAILED_INFRASTRUCTURE=4, ABORTED_LIMIT=5, BLOCKED_PREREQUISITE=6, NOT_EXECUTED=7, INCONCLUSIVE=8. Static-check exit zero denotes only metadata/syntax consistency. `writeRunReport(directory,result)` validates the strict envelope/digest and publishes an immutable new JSON file through a synced temporary file and hard link, refusing overwrite. Storage-platform support is unexecuted; an unsupported filesystem must fail rather than report publication success.
