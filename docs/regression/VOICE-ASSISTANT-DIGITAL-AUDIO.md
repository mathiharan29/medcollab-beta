# Voice Assistant digital audio investigation

## Vocle's existing Android path

`SpeechBridge.transcribeFile` already constructs the API 33+ digital input request. It extracts the WAV's `data` chunk to a temporary PCM file, opens that file read-only as a `ParcelFileDescriptor`, and supplies it as `EXTRA_AUDIO_SOURCE`. The request declares mono PCM16 and takes the sample rate from the WAV header. It sets `EXTRA_SEGMENTED_SESSION` to the audio-source extra and collects the top hypothesis from native result callbacks. This is the existing Needl Voice file-transcription path. The Home assistant ordinarily calls `startListening`, which uses the recognizer's microphone input. The existing `FR-AST-34` test calls the file API and passes its returned text to the real assistant before confirmation. [SpeechBridge](../../medcollab-app/android/app/src/main/kotlin/com/example/medcollab_app/SpeechBridge.kt#L113), [Flutter speech service](../../medcollab-app/lib/core/speech/speech_service.dart#L104), [FR-AST-34](../../medcollab-app/integration_test/functional_regression/voice_assistant_test.dart)

Android forwards the file descriptor to the selected recognition service. Android documents that service implementations may ignore the extra and open the microphone. Vocle uses the on-device factory when Android advertises it, then uses the default factory when on-device recognition is unavailable. The existing `fileInput` flag checks SDK level and service availability. An installed service, a positive language-support response and an installed language model are different signals, and none proves that the service reads a supplied file descriptor. Vocle retries language-unavailable and language-unsupported errors in another English locale. Recognition service disconnection leaves that retry path unused. [Android audio source contract](https://developer.android.com/reference/android/speech/RecognizerIntent#EXTRA_AUDIO_SOURCE), [Android recognition support](https://developer.android.com/reference/android/speech/RecognitionSupport)

### Format and lifecycle findings

| Check | Observation |
|---|---|
| Fixture decoding | All nine original fixture SHA-256 values matched the manifest. Python's WAV reader parsed each as uncompressed mono signed little-endian PCM16 at 16 kHz. The Bala fixture contains 38,373 frames and 76,746 raw bytes, with a peak of 29,073. The Alex probe checked the same format and found 54,209 frames and 108,418 raw bytes. |
| Production WAV parsing | The bridge checks the RIFF/WAVE signatures and locates the sample rate and data chunk. It assumes PCM16 and one channel. It does not validate the format, bit depth or channel-count fields, account for padding on odd-sized chunks, or reject an early end during the data copy. The checked-in Bala clip uses a compatible layout. |
| File descriptor | Vocle gives each language attempt its own read-only descriptor. A regular file signals EOF at the end of the PCM data. The independent pipe test closes the write end after the last byte so the reader sees EOF. |
| Cleanup | Vocle destroys the recognizer and closes its descriptor on native completion, error and language retry. Its 150-second callback returns an empty result and removes the temporary path. That callback does not expressly destroy the active file recognizer or close its descriptor. The bridge's dispose path manages the live recognizer and TTS separately. |
| Android availability | `isRecognitionAvailable`, `isOnDeviceRecognitionAvailable` and `checkRecognitionSupport` are recorded separately. The probe tests the default and on-device recognizers independently when available. |

## Independent hosted experiment

The [probe](../../tests/functional-regression/voice-audio/android-probe/AudioSourceProbe.java) compiles into a standalone instrumentation APK with no Vocle or Flutter runtime. The [workflow](../../.github/workflows/vocle-digital-audio-probe.yml) boots GitHub-hosted Ubuntu emulators with `-no-audio`. It runs API 35 Google APIs and API 36 Google Play images and records the fingerprint, registered services and selected default component. It validates the Bala WAV checksum, strips the RIFF container and offers the exact raw PCM. Equal-length silence is the negative control.

Each available recognizer receives the same format via both a regular file, as used by Vocle, and a pipe. The pipe starts empty and its measured capacity is smaller than the fixture. Writing all 76,746 bytes proves that a reader drained at least the excess over the idle capacity. The current gate accepts that evidence for both pipe inputs or a shared descriptor cursor at EOF for both regular-file inputs. It also requires the expected phrase for speech and a terminal result with no text for silence. The job records errors, transcripts, byte counts, file positions and language support. There is no audio playback. [Emulator audio switch](https://developer.android.com/studio/run/emulator-commandline), [Android audio source contract](https://developer.android.com/reference/android/speech/RecognizerIntent#EXTRA_AUDIO_SOURCE)

The baseline hosted API 35 Google APIs job advertised both factories. On-device support reported empty installed, downloadable, pending and online locale lists. Its speech and silence trials returned code 12 (`ERROR_LANGUAGE_NOT_SUPPORTED`). The default service was `com.google.android.tts/...GoogleTTSRecognitionService`. The default pipe accepted all 76,746 bytes for each input against a 65,536-byte idle capacity. At least 11,210 bytes were drained by a reader. Both regular-file and pipe sessions returned code 13 (`ERROR_LANGUAGE_UNAVAILABLE`) with zero transcript segments. This proves descriptor ingress for the default service and leaves speech-to-text unverified. The first API 36 Play Store job stopped at ADB authorization before instrumentation. [Baseline run and artifacts](https://github.com/mathiharan29/medcollab-beta/actions/runs/44023948757), [Android error codes](https://developer.android.com/reference/android/speech/SpeechRecognizer)

The follow-up booted both images after preparing the ephemeral ADB key before launch. On both, the default service advanced the borrowed regular-file descriptor to byte 76,746 in an offline-preferred speech session. It then returned error 13. Android's `triggerModelDownload` supplied no terminal callback within the 50-second observation window, and the subsequent offline-preferred attempts still returned error 13. On API 35, allowing online recognition yielded a terminal segment, “open heart attack,” for the speech clip and code 7 (`ERROR_NO_MATCH`) for silence. The experiment reproduced this pair on two hosted runs. The emulator had audio disabled and the clip was supplied only through the descriptor. This demonstrates digital speech-to-text by the default service with online recognition allowed. The wrong phrase failed the command gate. The API 36 comparison returned recognizer-busy for the speech input and no-match for silence. [First model-request run](https://github.com/mathiharan29/medcollab-beta/actions/runs/44024536510), [Both-image repeat](https://github.com/mathiharan29/medcollab-beta/actions/runs/44024775944)

The longer existing Bala clip was recognized as “open chat with Dr mama” on both images. API 35 reproduced it for both descriptor types, with positive ingestion evidence and a passing silence control. Those trials also failed the exact-target gate. To establish a separate smoke case without counting the Bala failures as a pass, the follow-up added a synthetic Alex fixture. Hosted API 35 returned “open chat with Dr Alex” from the regular file and the pipe. Both controls returned code 7 with no text, and both shared regular-file cursors advanced to 108,418 bytes. [Longer Bala comparison](https://github.com/mathiharan29/medcollab-beta/actions/runs/44025241189), [Alex standalone job](https://github.com/mathiharan29/medcollab-beta/actions/runs/44025810359/job/133845743460)

## Hosted Vocle action test

The Voice Assistant Digital Audio workflow runs on GitHub-hosted Ubuntu. It runs on relevant pushes to `master`, supports manual dispatch and backs the `voice-assistant-prerecorded` selection in Feature Regression. Its test-only launcher runs the regular-file experiment and then starts `FR-AST-34` on that same emulator. The case reads the newly generated raw final result from the native probe evidence. It verifies the WAV digest, fixture, Android fingerprint, terminal callbacks, descriptor position and silence before forwarding the result. Vocle uses its own assistant, directory, confirmation UI, router and repositories against a disposable backend. The app test asserts the exact resolved user ID, a single confirmed DM lookup and the exact visible conversation. [Digital audio workflow](../../.github/workflows/vocle-digital-audio-regression.yml), [Feature Regression](../../.github/workflows/vocle-feature-regression.yml)

This hosted variant uses the default Android recognizer with online processing permitted for the synthetic fixture. That setting may use Google's network. The production bridge retains its existing factory choice and offline preference. The standalone native probe supplies the recognition result and the actual app handles the action, so this run does not establish that production's offline-preferred configuration works on either hosted image. The usual local `FR-AST-34` path still calls `SpeechBridge.transcribeFile`, and the transcript-injection case `FR-AST-35` stays separate.

The combined hosted job passed `FR-AST-34` and recorded successful source verification and cleanup. Both regular-file sessions reached EOF. Speech produced one final segment, and the equal-length silence returned error 7 with zero segments. The app resolved the exact seeded doctor, showed confirmation with no early side effects, and opened exactly one conversation after confirmation. ## Alternatives if the hosted service cannot read the input

| Path | What it would validate | Tradeoff |
|---|---|---|
| Provision an Android recognizer and its English model | Platform `SpeechRecognizer` and Vocle's existing file bridge. | Closest to the app's current behavior. Requires a reproducibly installable service and model on a fresh image. A model download alone establishes language availability, so the descriptor and silence test remains necessary. [Android model download](https://developer.android.com/reference/android/speech/SpeechRecognizer#triggerModelDownload(android.content.Intent)) |
| Build an offline Android test adapter using Vosk or sherpa-onnx | Real Android-side recognition of the supplied audio, followed by the production parser, confirmation and app actions. | Can pin the engine, native libraries and model for hosted runs. Needs separate ABI and model-license checks and tests of synthetic names. Coverage applies to the test adapter's engine. [Vosk Android](https://alphacephei.com/vosk/android), [sherpa-onnx Android](https://k2-fsa.github.io/sherpa/onnx/android/index.html) |
| Run whisper.cpp on the hosted Linux runner | Real speech recognition of the WAV and Vocle's Android command-to-action path, with the generated transcript transferred to the test app. | Simpler offline setup with a pinned model. Recognition runs on the host, so this test leaves Android's speech service and file bridge outside its coverage. [whisper.cpp WAV input](https://github.com/ggml-org/whisper.cpp/blob/master/README.md#quick-start) |

The hosted result covers one digital-audio DM case. The Bala recognition errors remain recorded in the standalone runs. The Priya draft is covered by the existing deterministic transcript-injection case `FR-AST-35`.
