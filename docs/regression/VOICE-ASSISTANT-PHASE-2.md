# Voice Assistant digital audio regression

The prerecorded feature selection runs the Android API 35 Google APIs image on GitHub-hosted Ubuntu with emulator audio disabled. The test installs the native PCM probe, runs independent recognizer sessions with read-only regular file descriptors, and passes each recorded final transcript to the production Voice Bot in the disposable Vocle app on the same emulator. The launcher checks the fixture digest, Android fingerprint, native attempt identity and descriptor position before the app receives text. The default Android service allows online recognition for the synthetic WAVs. Phase 1 also validated an equal-length silence input and a pipe for the original Alex fixture, and the `FR-AST-34` gate still runs independently. [Baseline on master](https://github.com/mathiharan29/medcollab-beta/actions/runs/44037724841), [published evidence](https://github.com/mathiharan29/medcollab-beta/actions/runs/44037724841/artifacts/14309110769), [Android audio-source contract](https://developer.android.com/reference/android/speech/RecognizerIntent#EXTRA_AUDIO_SOURCE)

## Supported command inventory

The parser strips trailing sentence punctuation, collapses whitespace and compares lowercase text. Name matching considers names, handles, specialty and prefixes within the signed-in doctor's directory. It favors a person over a tied chat, shows at most five equally ranked choices, and asks the user to refine unmatched targets. A chosen target receives an actionable proposal and its own confirmation. An unhandled command can reach Claude when configured. The authenticated and onboarded backend validates tool actions and targets against its own scoped directory. An unavailable provider or an empty interpretation yields the help message. The hosted audio suite disables the provider so it can check the local grammar and real application actions reproducibly. ## Cases and fixtures

The functional catalog grows from 306 to 311 cases and the Android inventory from 15 to 20. The prerecorded selection grows from one to six cases. The corpus grows from 10 to 46 checked WAVs, including the original nine and the Phase 1 Alex sample. The manifest records exact utterances, provenance, voice, duration, gain and format. The attempt plan binds each fixture to a case, intent, stable fixture target label, action and repeat policy. The runner records the actual database IDs assigned for those labels. The new recordings include distinct eSpeak and Piper voices, fast/slow speech, reduced gain, a Caribbean English voice and generated silence. Existing British and US voices, paused and noise samples stay in the corpus. The two Piper voices synthesize audio only. Their training recordings are public domain. The GitHub jobs use the checked WAVs directly. Reports include the planned row even when app execution is blocked, and preserve native transcripts and individual failed attempts.

- `FR-AST-35` and the broader `voice-assistant` selection provide transcript-only assertions. The live microphone selection retains its configured runner requirement. The full backend and Flutter job retains its normal scope. [Layer definitions and existing coverage](VOICE-ASSISTANT.md)
- `batch/probe.json` records every native regular-file session. `device/digital-audio-attempts.json` and its Markdown equivalent combine recognition, interpretation, resolution and action postconditions. The recognition rate counts nonempty terminal speech across observed speech sessions. Wording and intent accuracy use their measured rows. Entity accuracy uses attempts where a target ID or choice set is expected. The action rate includes all planned attempts. Published results distinguish assertion failure, infrastructure blocking and unexecuted attempts.

## Remaining boundaries

The app receives a genuine result from an independent native recognizer on the same emulator. The production microphone and its offline-preferred bridge still have separate coverage. Bringing the PCM hook directly into that bridge would require a test-only Android build seam plus a compatible offline locale model. The prior stock emulator offline probe returned `ERROR_LANGUAGE_UNAVAILABLE`, so this phase retains the online-allowed native harness without a production change. The existing exposed duplicate-confirmation defect `FR-AST-25`, repeated delivery of the same final event `FR-AST-28` and session expiry `FR-AST-30` are transcript-level evidence. Actual microphone, provider interpretation with a live provider and reproducible Indian English voice generation remain outside the verified hosted audio matrix.
