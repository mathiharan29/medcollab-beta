# Vocle voice regression coverage audit

Baseline upstream `master` was `baaffee2410df818ec57ee58f2b78dff6c6606c4`. The 245-case selectable catalog mapped Voice Messaging to `FR-MED-04` and `FR-ADM-01`, Voice Assistant to `FR-AST-01` and Handoffs to 25 general-purpose cases including `FR-ADM-01`. The catalog had no native voice case or separately selectable Handoff Voice mapping.

`FR-MED-04` uploads a valid synthetic WAV, checks recipient download bytes and reloaded audio metadata in a space channel, and verifies invalid metadata and database cardinality. It has no transcript or walkie-talkie assertion. `FR-ADM-01` inserts synthetic rows and checks allowlisted metric counts. It has no recording, delivery, editing or playback assertions. `FR-AST-01` checks onboarding, anonymous capabilities, fallback, input length and database invariance with the provider disabled. `FR-HOF-01–04` exercise ordinary handoffs, including draft patient editing and concurrent lifecycle transitions. They do not attach audio. `FR-HOF-13` and `FR-MED-07` exercise patient file attachments without the dedicated voice-note field.

## Implementation and evidence

- Needl Voice is a separate route over the same chat ID and audio messages as the regular chat. The view handles press/drag/lock and calls the shared recorder. The cubit uploads WAV, sends a pending audio message, then applies transcription from the speaker's device. The message API patches transcript content, emits `message_updated`, and search matches visible transcripts. [Voice page](../../medcollab-app/lib/features/needl_voice/presentation/needl_voice_page.dart), [voice cubit](../../medcollab-app/lib/features/needl_voice/presentation/needl_voice_cubit.dart), [recorder and player](../../medcollab-app/lib/features/messages/presentation/widgets/voice_note.dart), [messages controller](../../medcollab-backend/src/features/messages/message.controller.js), [search controller](../../medcollab-backend/src/features/search/search.controller.js)
- Handoff Voice uploads both levels through media context `handoff`, with independent shift and patient fields. The editor tracks uploads and optimistic content versions. The server normalizes trusted media and audit metadata, atomically guards content edits by version, and returns the latest handoff on conflict. Playback shares the chat player. [Voice field and player](../../medcollab-app/lib/features/handoffs/presentation/widgets/handoff_voice_note_field.dart), [patient editor](../../medcollab-app/lib/features/handoffs/presentation/widgets/patient_editor_sheet.dart), [form cubit](../../medcollab-app/lib/features/handoffs/presentation/cubit/handoff_form_cubit.dart), [handoff controller](../../medcollab-backend/src/features/handoffs/handoff.controller.js)
- The bot accepts recognizer events and typed text, tries the local parser first, then optionally asks the backend for proposals. The app confirmation card calls the executor, which uses the normal authenticated repositories. The backend never runs the proposed actions. A confirmed handoff action creates a draft for review. [Bot sheet](../../medcollab-app/lib/features/voice_bot/presentation/voice_bot_sheet.dart), [bot cubit](../../medcollab-app/lib/features/voice_bot/presentation/voice_bot_cubit.dart), [parser](../../medcollab-app/lib/features/voice_bot/domain/voice_command_parser.dart), [executor](../../medcollab-app/lib/features/voice_bot/data/voice_action_executor.dart), [assistant controller](../../medcollab-backend/src/features/assistant/assistant.controller.js), [speech adapter](../../medcollab-app/lib/core/speech/speech_service.dart)

### Reading the matrix

Coverage level describes the baseline assertions for the specific scenario. **FULL** covers that row at its stated boundary, **PARTIAL** covers only the listed subset, **MISSING** means no assertion for that behavior, and **DEVICE_ONLY** marks facts that need OS or hardware evidence. A proposed regression ID refers to the executable added or promoted by this audit. Manual IDs below are device protocols outside the executable catalog. Run results appear separately from coverage.

Existing test references use the following file names and their original check numbers. The four Flutter developer suites now live in `test/functional_regression`, where hosted and selectable runs execute their original assertions. The ten message parser phrase variants retain all assertions under one case.

- **Voice API** and **Handoff API** are the standalone developer checks. [Voice API](../../medcollab-backend/tests/api/voice-features.test.mjs), [Handoff API](../../medcollab-backend/tests/api/handoff-voice.test.mjs)
- **Voice cubit**, **handoff voice**, **bot cubit**, **parser**, and **shared voice** are Flutter tests with injected recorder/player/speech or repository seams. [Voice cubit](../../medcollab-app/test/functional_regression/needl_voice_cubit_test.dart), [handoff voice](../../medcollab-app/test/functional_regression/handoff_voice_test.dart), [bot cubit](../../medcollab-app/test/functional_regression/voice_bot_cubit_test.dart), [parser](../../medcollab-app/test/functional_regression/voice_command_parser_test.dart), [shared voice](../../medcollab-app/test/functional_regression/voice_note_test.dart)
- **Beta device** and **contacts device** are standalone developer integration scenarios. Screenshot capture, printed transcript status and control visibility count only for what their assertions actually observe. [Beta device](../../medcollab-app/integration_test/vocle_beta_1114_test.dart), [contacts device](../../medcollab-app/integration_test/vocle_contacts_voice_test.dart)

## Validation

All cases used the upstream application revision named above and the expanded working-tree regression harness. The catalog now has 296 IDs, including 188 backend, 98 Flutter and 10 local-only Android cases. This audit adds 51 catalog IDs. It promotes 31 from existing Flutter assertions and adds 20 new executable cases. The ranges are `FR-VCE-01–16`, `FR-HOF-14–24` and `FR-AST-02–25`.

| Run | Result |
| --- | --- |
| Full backend catalog | All 188 IDs recorded, with 184 PASS, 3 FAIL and 1 NEEDS_DECISION. FR-HOF-02 still accepts an invalid shift date, FR-NDL-28 still fails its concurrent expansion assertion, FR-NDL-29 still fails its history-recovery assertion, and FR-NDL-10 still needs a decision on archived Needl expansion. |
| Selectable voice backend | Voice Messaging 5/5, Handoff Voice 3/3, Voice Assistant 2/2. All seven new backend cases passed. |
| Existing developer voice APIs | 23/23 passed on a disposable backend. Voice API 12/12 and Handoff API 11/11. |
| Full Flutter catalog | All 98 IDs executed on Flutter 3.29.3. 92 PASS and 6 FAIL, including the existing FR-NDL-39 and FR-NDL-53 failures. |
| Selectable voice Flutter | Voice Messaging 9 PASS and 3 FAIL, Handoff Voice 11 PASS, Voice Assistant 22 PASS and 1 FAIL. Each run matched the exact selected IDs. |
| Android voice journeys | FR-VCE-14 and FR-HOF-24 passed in local emulator runs on Android API 36. Needl Voice verified denied and discarded capture, one delivered WAV, persisted history and replay. The emulator exercised the unavailable transcript fallback. Handoff Voice verified recording and saving both audio fields, then replaying both as the recipient. |
| Catalog and tooling contracts | Catalog, selectors, reporting, and developer workflow contracts passed. |

The new Flutter failures remain active in the regression suites.

- `FR-VCE-12` reproduces an older history reply replacing a newer live clip and its transcript.
- `FR-VCE-15` reproduces a newly arriving clip taking over the player while a clip is paused.
- `FR-VCE-16` reproduces a failed media load leaving a healthy queued successor idle.
- `FR-AST-25` reproduces two executor calls from a second Send tap while the first confirmed action is pending.

## Remaining native protocols

Use a disposable debug install and synthetic users A, B and C, with A/B in an accepted 1:1 DM, those users and C in a Needl, and a shared ward where A can hand off to B. Use an Android phone with an enabled English (India) recognizer for speech assertions. Use only synthetic phrases, a separate device or emulator for B, and an isolated local backend. Capture Android API level, app SHA, OS permission status, time, A/B case identifiers, and the exact message or handoff ID for each observation.
