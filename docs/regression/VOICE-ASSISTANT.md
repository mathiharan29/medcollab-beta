# Home Voice Assistant regression

## Recognition and action chain

1. The authenticated Home header opens the assistant sheet and starts listening. **PlatformSpeechService** calls **SpeechBridge** through `vocle/speech` and subscribes to `vocle/speech/events`. The mic button stops capture while listening. Closing the sheet cancels capture and stops speech output. [Home header](../../medcollab-app/lib/features/home/presentation/pages/home_dashboard_page.dart), [launcher](../../medcollab-app/lib/features/voice_bot/presentation/voice_bot_launcher.dart), [sheet](../../medcollab-app/lib/features/voice_bot/presentation/voice_bot_sheet.dart)
2. Android uses its on-device recognizer when available and otherwise uses the system default recognizer, requesting offline recognition. The preferred locale is `en-IN`. Language errors can trigger pack download and fall back to the device's English locale and `en-US`. The bridge emits level, partial, final and error events. Android's recognition service controls model availability and offline behavior. [SpeechBridge](../../medcollab-app/android/app/src/main/kotlin/com/example/medcollab_app/SpeechBridge.kt), [Flutter adapter](../../medcollab-app/lib/core/speech/speech_service.dart)
3. The Cubit processes the final transcript or typed request. The local directory is built from DMs, Needls, spaces, channels and accessible group members, excluding the signed-in user. Matching uses normalized name tokens, usernames, speciality and prefixes. Ties favor people over chat names and same-category ties ask the user to choose. An unmatched name can yield a clarification with no choices. Local clarification counts as understood, so it bypasses AI. [Cubit](../../medcollab-app/lib/features/voice_bot/presentation/voice_bot_cubit.dart), [directory](../../medcollab-app/lib/features/voice_bot/data/voice_bot_repository.dart), [parser](../../medcollab-app/lib/features/voice_bot/domain/voice_command_parser.dart)
4. An unhandled command can go to the Claude provider if the backend reports it is configured. Both assistant endpoints require authentication and onboarding. The API looks up its own user-scoped directory and validates returned tool actions and targets before sending proposals to the app. With AI disabled, declined or unavailable, the user can get the help hint or a clarification. The local test backend disables real providers. [Assistant routes](../../medcollab-backend/src/features/assistant/assistant.routes.js), [Assistant controller](../../medcollab-backend/src/features/assistant/assistant.controller.js), [provider contracts](../../tests/functional-regression/suites/assistant.mjs)
5. The Cubit enters confirmation, then executes only the selected proposal. A choice chip resolves a target and brings up its own confirmation. Cancel removes the proposal. The executor uses existing authenticated repositories and routes. The person DM endpoint checks that contact is permitted, and the handoff API checks sender and recipient membership and channel ownership before storing a draft. Submission is a separate endpoint and user action. [Executor](../../medcollab-app/lib/features/voice_bot/data/voice_action_executor.dart), [DM controller](../../medcollab-backend/src/features/channels/channel.controller.js), [handoff controller](../../medcollab-backend/src/features/handoffs/handoff.controller.js)

## Audio fixtures and replay

The [manifest](../../tests/functional-regression/voice-audio/manifest.json) records the phrase, voice settings, expected target and SHA-256 for each WAV. These are generated eSpeak NG formant voices with verified UK and US locale profiles, two kinds of voice timbre, several pitch and speed settings, a pause, and deterministic low-amplitude background noise. Bala/Bela are distinct samples and synthetic people. No consented speech or verified Indian English voice was available in the local synthesizer. To regenerate with Python 3.12, install `espeakng-loader==0.2.4` and run `python tests/functional-regression/voice-audio/generate.py`. The repository includes the generated utterances, with no synthesizer binaries or model data. [eSpeak NG source and license](https://github.com/espeak-ng/espeak-ng)

The live test replays PCM through the SDK emulator's client-streaming `injectAudio` RPC. Android opens the normal microphone through `SpeechBridge.startListening`. Before asserting recognition, the test opens a separate Android microphone recording and checks that replay increases the captured signal over the quiet baseline. The test observes the native method acknowledgement and native events while preserving their messages and normal callbacks. `EXTRA_AUDIO_SOURCE` is used only by Vocle's separate file-input recognizer. Android documents that recognition services can ignore that extra. Windows playback to the host speakers has no verified path to the guest microphone on this machine. [Emulator gRPC](https://developer.android.com/studio/run/emulator-console), [emulator microphone settings](https://developer.android.com/studio/run/emulator-extended-controls), [recognizer file-source API](https://developer.android.com/reference/android/speech/RecognizerIntent#EXTRA_AUDIO_SOURCE)

## Run the suites

- **Transcript and provider contracts** select `voice-assistant` in Feature Regression. For local Flutter runs, set `VOCLE_FEATURE=voice-assistant` and use the [selective runner](FEATURE-REGRESSION.md).
- **Live Android** select **Voice Assistant — Live Audio** on `master`. A dedicated self-hosted Linux runner labeled `vocle-live-audio` needs the usual [Android device prerequisites](../VOCLE_FUNCTIONAL_REGRESSION_DEVICE_RUNNER.md), Python with `grpcio`, and one booted disposable Android emulator with a working recognition service and English speech packs. Start the emulator with audio enabled and `-grpc 8562 -grpc-use-token`. Set `VOCLE_EMULATOR_DISCOVERY` to that process's emulator discovery INI and, if needed, `VOCLE_PYTHON` to its Python executable. Enable repository variable `VOCLE_LIVE_AUDIO_RUNNER=enabled` after provisioning. Dispatch without the variable or from another branch reports **NOT EXECUTED** and fails.
- **Local Android** use the same prerequisites, then run `node tests/functional-regression/scripts/run-device.mjs --cases=FR-AST-31,FR-AST-32,FR-AST-33 --output=<fresh-directory>`. Set `VOCLE_VOICE_REPETITIONS` to 1–10 to repeat the canonical Bala and Priya clips. Default is 3. The remaining clips run once per case. It records every outcome and never retries an audio assertion.
- **Prerecorded file recognition** run locally with `node tests/functional-regression/scripts/run-device.mjs --cases=FR-AST-34 --output=<fresh-directory>`. This requires Android 13+ and a recognizer that honors file input. The feature inventory lists the case independently of the microphone suite.
- **Android deterministic persistence** run locally with `node tests/functional-regression/scripts/run-device.mjs --cases=FR-AST-35 --output=<fresh-directory>`. This runs without microphone or file recognition.
- **Full Android catalog on a compatible runner** supply all Android IDs with `--cases`. The no-options device run retains the standard Android cases. Hosted `all` preserves its backend and Flutter executions and lists the platform-dependent Android cases as unexecuted.

The native runner writes `voice-assistant-attempts.md`, `voice-assistant-attempts.json`, device phase logs and source/cleanup evidence. The JSON records start, recognized transcript or error, proposal, confirmation, target, actual navigation or persistence and cause per attempt. A blocked transport probe yields unexecuted rows and an infrastructure failure. A recognition failure after successful startup and delivery counts as a failed attempt. File recognition and live audio have independent denominators.
